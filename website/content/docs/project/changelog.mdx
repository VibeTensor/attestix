## [0.4.1] - 2026-06-24

Stable. Rolls up the 0.4.1rc1 security hardening and the 0.4.1rc2 post-quantum signing into one release. Install with `pip install attestix`.

### Added
- **Post-quantum / hybrid signing** (`attestix.auth.pqc`, optional `[pqc]` extra): FIPS 204 ML-DSA-65 sign/verify over the shared canonical form, and a hybrid Ed25519 + ML-DSA-65 composite where a verifier must validate both signatures. `did:key` Multikey encoding for ML-DSA-65. The default Ed25519 path is unchanged, and the default services do not use the post-quantum signer. Cryptosuites: `mldsa65-jcs-2026`, `hybrid-ed25519-mldsa65-jcs-2026`.

### Security
- **Credential verification key-binding (High).** `verify_credential`, `verify_credential_external` and `verify_presentation` now decode the Ed25519 key from the trust anchor (`issuer.id` for credentials, the server DID for presentations) and reject a `verificationMethod` that names a different DID, closing an issuer key-substitution masquerade.
- **Fail-closed API auth (High).** The REST `APIKeyMiddleware` now refuses non-public requests (503) when `ATTESTIX_API_KEY` is unset, unless `ATTESTIX_ALLOW_NO_AUTH` is explicitly set (development/tests only).
- **Dependency CVE floors (High).** `requirements.txt` pins `cryptography>=46.0.7` and `PyJWT[crypto]>=2.12.0` to match `pyproject.toml`.

### Fixed
- **Cloud-to-self-host audit-chain re-verification.** The importer now preserves each row's chain tenant verbatim and persists the audit chain under it, so bundles minted under a cloud workspace ID import and re-verify cleanly.
- Bundle import reads the cloud `vc_jsonld` credential key, so credentials in cloud bundles import correctly.

## [0.4.0] - 2026-05-30

First stable 0.4.0: the embeddable, multi-tenant, portable foundation. Promotes `0.4.0rc5` unchanged.

### Added
- **Pluggable storage and signer seams** (`Repository` / `Signer` protocols). The package ships the file and in-memory repositories and the in-process Ed25519 signer; the `[pg]` and `[kms]` extras install drivers only, and the Postgres and KMS adapter modules are not included in the package.
- **Multi-tenancy.** Resources carry `tenant_id`; structured, hash-chained, idempotency-aware audit events (`audit.json`) are chained per tenant and do not leak across tenants.
- **Portability.** Bundle export and import (`attestix export` / `attestix import`) with a byte-stable canonical JSON wire format (see the bundle spec at [attestix.io/spec/bundle/v1](https://attestix.io/spec/bundle/v1)).
- **Offline JS verifier** for Python-issued credentials, now published on npm as `attestix` (the earlier scoped `@vibetensor/attestix` package is superseded).
- **Structured `verify_chain`** returning `VerifyChainResult` with `broken_event_id` and `failure_reason`.
- **Canonical `attestix.*` namespace** with back-compat shims; `[api]`, `[langchain]`, `[crewai]`, `[openai-agents]` install extras; LangChain (`AttestixCallbackHandler`), OpenAI Agents SDK (`AttestixAuditHook`), and CrewAI (`AttestixCrewAdapter`) integrations shipped in the wheel.
- **REST idempotency** replays the original cached body verbatim (`Idempotency-Replayed` header), exactly-one-resource dedup, 24h TTL.
- **Docs:** per-audience quickstarts; OWASP Agentic Top 10, ISO/IEC 42001, NIST AI RMF, SOC 2, and FRIA mapping pages; a browser verification page; the bundle spec page.
- **Supply chain:** Docker base images SHA-pinned, CI dependencies hash-pinned (`--require-hashes`).

### Changed
- `generate_declaration_of_conformity` reports all missing prerequisites at once; declarations surface `credential_id`.

### Known issues (at release)
- `get_audit_trail` returns only the legacy Article 12 `log_action` chain, not the structured audit events.
- `create_delegation` refuses capability escalation by returning an error dict rather than raising (escalation is still blocked).

## [0.3.0] - 2026-04-17

Security hardening release bundling seven previously merged but unreleased pull requests (#45 through #51): a critical delegation auth-bypass fix, corrected Article 43 Annex III conformity logic, three framework integrations, and GitHub Actions CI/CD. No breaking API changes for MCP tool callers.

### Security
- **Critical: delegation chain auth bypass fixed** (#45). Parent tokens in a delegation chain are now fully verified and capability attenuation is enforced when a parent token is supplied. Previously a delegate could craft a child token claiming more capabilities than its parent. Long-lived delegation tokens issued before this release should be reviewed and re-issued.
- **SSRF hardening** (#47). Agent discovery, DID resolution, and credential fetch paths go through the centralized SSRF guard (private IP blocking, metadata endpoint blocking, DNS rebinding defence) on every outbound request.
- **Timing-safe comparisons** (#47). Signature and token equality checks use `hmac.compare_digest`.
- **API error sanitization** (#47). REST API exception paths no longer leak stack traces, file paths, or internal type names.

### Added
- **LangChain integration** (#42): a `BaseCallbackHandler` subclass that logs LLM, chain, and tool events into the Attestix audit trail.
- **OpenAI Agents SDK integration** (#48): connects the OpenAI Agents runtime to the Attestix MCP server over stdio via `MCPServerStdio`.
- **CrewAI integration** (#51): uses `MCPServerAdapter` so CrewAI crews can load Attestix tools like any other MCP toolset.

### Fixed
- **Article 43 Annex III conformity assessment** (#46). Self-assessment is now permitted for high-risk profiles with `annex_iii_category` set to points 2-8 and blocked for point 1 (biometrics) or when the category is unspecified.
- **EAS schema UID derivation** (#50). The schema UID is derived with the same encoding EAS uses (schema string, resolver address, revocable flag).
- **Attested event decoding hardened** (#50). Receipt logs are decoded through web3.py's ABI-level event processing, with a topic-signature fallback.
- Test mock log shape updated so the hardened decoder path is exercised in CI.

### Infrastructure
- **GitHub Actions CI/CD** (#49): pytest matrix (Python 3.10-3.13) on pull requests plus `ruff`, `mypy`, `bandit`, and `pip-audit` jobs; a release workflow publishes to PyPI on tag push.
- Default pytest `addopts` include `-p no:logfire` to avoid an OpenTelemetry ABI import error pulled in via CrewAI.

## [0.1.0] - 2026-02-19

Initial public release.

### Added

**Identity & Trust (19 tools)**
- Identity module (7 tools): create, resolve, verify, translate, list, get, revoke agent identities via Unified Agent Identity Tokens (UAITs)
- Agent Cards module (3 tools): parse, generate, and discover Google A2A-compatible agent cards
- DID module (3 tools): create did:key and did:web identifiers, resolve any DID via Universal Resolver
- Delegation module (3 tools): UCAN-style capability delegation with EdDSA-signed JWT tokens
- Reputation module (3 tools): recency-weighted trust scoring with category breakdown

**EU AI Act Compliance (17 tools)**
- Compliance module (6 tools): risk categorization (minimal/limited/high), conformity assessments (Article 43), Annex V declarations of conformity
- Credentials module (6 tools): W3C Verifiable Credentials (VC Data Model 1.1) with Ed25519 proofs labelled `Ed25519Signature2020` over Attestix's RFC 8785-style canonical JSON (verify with the Attestix verifiers), Verifiable Presentations
- Provenance module (5 tools): training data provenance (Article 10), model lineage (Article 11), audit trail (Article 12)

**Infrastructure**
- Ed25519 cryptographic signing for all persistent records
- JSON file storage with file locking and corruption recovery
- Lazy service initialization with TTL cache
- MCP server via FastMCP with stderr-safe logging
- PyPI packaging via pyproject.toml

**Documentation**
- Getting Started guide
- EU AI Act Compliance workflow guide
- Risk Classification decision tree
- Concepts reference (UAIT, DID, VC, VP, UCAN, Ed25519)
- Complete API reference for all tools
- Integration guide (LangChain, CrewAI, AutoGen, MCP client)
- FAQ
- 5 runnable example scripts

### Security

- Private keys never returned in MCP tool responses (stored locally in .keypairs.json)
- Mutable fields (proof, credentialStatus) excluded from VC signature payloads
- High-risk systems blocked from self-assessment (requires third-party per Article 43)
- SSRF protection on agent discovery URLs
- All sensitive files excluded from git (.signing_key.json, .keypairs.json, .env)
