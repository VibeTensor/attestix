The OpenAI Agents SDK consumes Attestix as a native MCP server over stdio. All 47 tools are discovered automatically, with no per-tool wrapping. For explicit audit logging from your own code, Attestix also ships a small helper class, `AttestixAuditHook`.

## Install

```bash
pip install "attestix[openai-agents]"
```

The extra pins `openai-agents>=0.0.20`. The snippets below use `MCPServerStdio`, `create_static_tool_filter`, and `Runner`; check them against the SDK version you install.

## Minimal wiring

The Attestix MCP server speaks stdio only. Launch it with `python -m attestix.main`. `MCPServerStdio` is an async context manager; wrap it in `async with` so the subprocess closes cleanly when the run ends.

```python
import asyncio
import sys
from agents import Agent, Runner
from agents.mcp import MCPServerStdio

async def main():
    async with MCPServerStdio(
        name="Attestix",
        params={"command": sys.executable, "args": ["-m", "attestix.main"]},
    ) as attestix:
        agent = Agent(
            name="quarterly-analyst",
            instructions="You are a financial analyst.",
            mcp_servers=[attestix],
        )
        result = await Runner.run(agent, input="Run Q4 analysis")
        print(result.final_output)

asyncio.run(main())
```

Using `sys.executable` makes sure the server runs in the same Python environment where `attestix` is installed.

## Restricting which tools are exposed

Use `tool_filter` with `create_static_tool_filter` to scope the Attestix tool surface for a given agent.

```python
from agents.mcp import MCPServerStdio, create_static_tool_filter

attestix_filter = create_static_tool_filter(
    allowed_tool_names=[
        "create_agent_identity",
        "issue_credential",
        "record_training_data",
    ],
)

async with MCPServerStdio(
    name="Attestix",
    params={"command": sys.executable, "args": ["-m", "attestix.main"]},
    tool_filter=attestix_filter,
    cache_tools_list=True,
) as attestix:
    agent = Agent(
        name="compliance-agent",
        mcp_servers=[attestix],
    )
```

## What gets audited

Calling Attestix tools through MCP does not audit every call. Only state-changing operations (for example `create_agent_identity`, `issue_credential`, `revoke_credential`, `create_delegation`, `record_training_data`, `log_action`) emit a structured event to the hash-chained audit log in `~/.attestix/audit.json`. Read-only tools such as `get_identity`, `verify_credential`, or `list_credentials` do not emit events, and the SDK's own tool calls to non-Attestix tools are not seen by Attestix at all.

To record your agent's own decisions, call the `log_action` MCP tool or use `AttestixAuditHook` below.

## AttestixAuditHook

`AttestixAuditHook` (in `attestix.integrations.openai_agents`) is a plain helper class, not an SDK hook that registers itself. You call its methods explicitly from your guardrails or tool wrappers; each call writes one `log_action` entry to the Attestix audit log (hash-chained per agent and signed with the Attestix server key).

```python
from attestix.integrations.openai_agents import AttestixAuditHook

hook = AttestixAuditHook(
    agent_id=None,                # existing Attestix agent_id; None = auto-create
    display_name="OpenAIAgent",   # only used when auto-creating
    issuer_name="self",           # only used when auto-creating
)

# In an input guardrail:
hook.log_guardrail_decision(
    allowed=False,
    reason="compliance profile incomplete",
    details={"missing": ["human_oversight"]},
)

# Around a tool call you want on the record:
hook.log_tool_call(
    tool_name="fetch_ledger",
    input_summary="quarter=Q4",
    output_summary="412 rows",
)

print(hook.get_audit_summary()["audit_entries"])
```

- `log_guardrail_decision(*, allowed, reason, details=None)` logs `action_type="delegation"` with `input_summary` `guardrail.decision: ALLOW` or `BLOCK`.
- `log_tool_call(*, tool_name, input_summary="", output_summary="")` logs `action_type="external_call"`.
- `get_audit_summary()` returns `agent_id`, `audit_entries`, and `trail` (from `get_audit_trail`, which returns at most 50 entries by default).

When `agent_id` is `None`, a new identity is created on every construction; pass a stable `agent_id` to attribute all runs to one agent.

## Streaming and tool-use events

`Runner.run_streamed` returns a `RunResultStreaming`. Iterate its `stream_events` async iterator.

```python
result = Runner.run_streamed(agent, input="Run Q4 analysis")
async for event in result.stream_events():
    if event.type == "run_item_stream_event" and event.name == "tool_called":
        print(event.item)
```

After the run, inspect entries with the `get_audit_trail` MCP tool, `ProvenanceService().get_audit_trail(agent_id)`, or `attestix audit <agent_id>` on the CLI.

## HTTP transport

The Attestix MCP server does not offer an HTTP transport; there is no `--transport http` option and `MCPServerStreamableHttp` cannot connect to it. If Attestix must run as a separate service, use the REST API instead:

```bash
pip install "attestix[api]"
export ATTESTIX_API_KEY="change-me"   # clients send it in the X-API-Key header
uvicorn attestix.api.main:app --port 8000
```

Call it from your own function tools. Without `ATTESTIX_API_KEY` (or `ATTESTIX_ALLOW_NO_AUTH=1` for local development), non-public REST paths return 503.

## Multi-agent orchestration

You can give every agent in an orchestration access to the same Attestix server:

```python
async with MCPServerStdio(
    name="Attestix",
    params={"command": sys.executable, "args": ["-m", "attestix.main"]},
) as attestix:
    analyst = Agent(name="analyst", mcp_servers=[attestix])
    summarizer = Agent(name="summarizer", mcp_servers=[attestix])
    supervisor = Agent(
        name="supervisor",
        mcp_servers=[attestix],
        handoffs=[analyst, summarizer],
    )
    await Runner.run(supervisor, input="Prepare the Q4 board pack.")
```

SDK hand-offs are not recorded automatically, and Attestix does not create delegations for them. If you want a hand-off on the record, log it yourself (for example `hook.log_tool_call(tool_name="handoff:analyst")`) and, if the receiving agent should hold scoped rights, issue a UCAN-style delegation token (a server-signed JWT) with the `create_delegation` tool.
