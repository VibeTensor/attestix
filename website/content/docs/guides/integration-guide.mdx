Attestix ships helper classes for three agent frameworks in the `attestix.integrations` package (LangChain, OpenAI Agents SDK, and CrewAI; importable from the wheel since v0.4.0) and works with any MCP-compatible client through its stdio MCP server. The current release is 0.4.1. Attestix is pre-1.0 software: pin the version you depend on.

## Example integrations via MCP

Any MCP client that can launch a stdio server can consume Attestix. The repository also contains example scripts for other frameworks in [`integrations/examples/`](https://github.com/VibeTensor/attestix/tree/main/integrations/examples). These are illustrative only: they simulate the framework runtime (no framework install needed) and call Attestix services directly. They are not shipped integrations or reference configs.

- Dify (`dify_compliance.py`)
- Google ADK (`google_adk_compliance.py`)
- Microsoft Semantic Kernel (`semantic_kernel_compliance.py`)
- AWS Strands Agents (`strands_compliance.py`)

For desktop MCP clients such as Claude Desktop, Cursor, Continue, Windsurf, or VS Code, use the generic stdio configuration below. Attestix does not ship client-specific configs for them.

## As a plain Python library

You can import Attestix services directly without running the MCP server.

```python
from attestix.services.identity_service import IdentityService
from attestix.services.credential_service import CredentialService
from attestix.services.compliance_service import ComplianceService
from attestix.services.provenance_service import ProvenanceService

identity_svc = IdentityService()
credential_svc = CredentialService()
compliance_svc = ComplianceService()
provenance_svc = ProvenanceService()

agent = identity_svc.create_identity(
    display_name="quarterly-analyst-v2",
    source_protocol="manual",
    capabilities=["data_analysis", "reporting"],
    issuer_name="VibeTensor",
    expiry_days=365,
)
```

All services share the same Ed25519 server signing key (auto-generated on first use) and the same JSON storage files, both under `~/.attestix` by default (override with `ATTESTIX_DATA_DIR`).

## As an MCP server (stdio)

The MCP server speaks stdio only. Launch it with `python -m attestix.main`:

```json
{
  "mcpServers": {
    "attestix": {
      "command": "python",
      "args": ["-m", "attestix.main"]
    }
  }
}
```

Use the full path to the Python interpreter of the environment where `attestix` is installed if `python` on the client's PATH points elsewhere.

## Over HTTP (REST API)

The MCP server has no HTTP transport. For network access, run the REST API instead:

```bash
pip install "attestix[api]"
export ATTESTIX_API_KEY="change-me"
uvicorn attestix.api.main:app --port 8000
```

Clients send the key in the `X-API-Key` header. If neither `ATTESTIX_API_KEY` nor `ATTESTIX_ALLOW_NO_AUTH=1` (local development only) is set, non-public paths return 503.
