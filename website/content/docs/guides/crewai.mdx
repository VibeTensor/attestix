CrewAI agents receive Attestix tools through the `tools` field, populated by CrewAI's `MCPServerAdapter` over stdio. Every agent in the crew can discover all 47 Attestix tools. For an audit trail of the crew's task graph, Attestix also ships `AttestixCrewAdapter`, a small helper you call from your task callbacks.

## Install

```bash
pip install "attestix[crewai]" crewai-tools
```

The `[crewai]` extra installs `crewai` (`>=0.95,<0.200`). `MCPServerAdapter` lives in `crewai-tools`, and `StdioServerParameters` comes from the `mcp` package (already an Attestix dependency).

## Minimal wiring

`MCPServerAdapter` is a context manager that yields the discovered tool list. The Attestix MCP server is stdio only; launch it with `python -m attestix.main`.

```python
import sys
from crewai import Agent, Crew, Task
from crewai_tools import MCPServerAdapter
from mcp import StdioServerParameters

server_params = StdioServerParameters(
    command=sys.executable,
    args=["-m", "attestix.main"],
)

with MCPServerAdapter(server_params) as attestix_tools:
    analyst = Agent(
        role="Financial analyst",
        goal="Analyse quarterly data",
        backstory="Senior quant with 10 years of regulatory reporting experience.",
        tools=attestix_tools,
    )

    task = Task(
        description="Produce the Q4 report",
        agent=analyst,
        expected_output="A Q4 report summary.",
    )

    crew = Crew(agents=[analyst], tasks=[task])
    result = crew.kickoff()
```

Giving agents the tools does not by itself audit the crew. Attestix records an audit event only when a state-changing Attestix tool is actually called (for example `create_agent_identity`, `issue_credential`, `log_action`).

## Logging the task graph with AttestixCrewAdapter

`AttestixCrewAdapter` (in `attestix.integrations.crewai`) does not import or hook into CrewAI itself. You call it from your own CrewAI task callbacks, and each call writes one `log_action` entry (`action_type="data_access"`) to the Attestix audit log, hash-chained per agent and signed with the Attestix server key.

```python
from attestix.integrations.crewai import AttestixCrewAdapter

adapter = AttestixCrewAdapter(
    agent_id=None,               # existing Attestix agent_id; None = auto-create
    display_name="ResearchCrew", # only used when auto-creating
    issuer_name="self",          # only used when auto-creating
)

adapter.log_task_start(task_name="research", agent_role="researcher", inputs={"quarter": "Q4"})
# ... run the task ...
adapter.log_task_finish(task_name="research", output_summary="3 documents summarised")

print(adapter.get_audit_summary()["audit_entries"])
```

- `log_task_start(*, task_name, agent_role="", inputs=None)` stores `inputs` as a string, truncated to 500 characters.
- `log_task_finish(*, task_name, output_summary="")` stores the summary truncated to 500 characters.
- When `agent_id` is `None`, a new identity is created on every construction; pass a stable `agent_id` to attribute all runs to one agent.

## Crew-wide compliance profile

A compliance profile is attached to an existing Attestix identity, so create the identity first:

```python
from attestix.services.identity_service import IdentityService
from attestix.services.compliance_service import ComplianceService

crew_identity = IdentityService().create_identity(
    display_name="crew-q4-report",
    source_protocol="manual",
)

profile = ComplianceService().create_compliance_profile(
    agent_id=crew_identity["agent_id"],
    risk_category="minimal",  # classify your own system; see the risk classification guide
    provider_name="VibeTensor",
    intended_purpose="Quarterly financial analysis for board review",
)
```

`create_compliance_profile` returns `{"error": ...}` if the agent does not exist or already has a profile. Audit entries are not linked to the profile automatically; they are linked by `agent_id`, so use the same `agent_id` for `AttestixCrewAdapter` if you want one trail per crew.

## Role hand-offs

CrewAI delegation between agents is not recorded by Attestix, and no delegation tokens are created for it. If you need a hand-off on the record, log it with `adapter.log_task_start(...)` / `log_task_finish(...)`, and if the receiving agent should hold scoped rights, issue a UCAN-style delegation token (a server-signed JWT) with the `create_delegation` MCP tool or `DelegationService`.

## Sequential vs hierarchical crews

Both topologies work with `MCPServerAdapter`:

```python
from crewai import Crew, Process

with MCPServerAdapter(server_params) as attestix_tools:
    manager = Agent(role="Manager", tools=attestix_tools, ...)
    analyst = Agent(role="Analyst", tools=attestix_tools, ...)
    reviewer = Agent(role="Reviewer", tools=attestix_tools, ...)

    crew = Crew(
        agents=[analyst, reviewer],
        tasks=[report_task],
        process=Process.hierarchical,
        manager_agent=manager,
    )
    result = crew.kickoff()
```

Nothing flows down automatically in a hierarchical crew: the compliance profile stays attached to the identity you created it for.

## Bundling credentials for a reviewer

No credential is issued per task automatically. If you issue credentials yourself (for example with `CredentialService().issue_credential(...)` or the `issue_credential` tool), you can bundle those that belong to one agent into a Verifiable Presentation:

```python
from attestix.services.credential_service import CredentialService

vp = CredentialService().create_verifiable_presentation(
    agent_id=crew_identity["agent_id"],
    credential_ids=[credential_id],
    audience_did="did:web:eu.regulator",
    challenge="ch_q4_2026",
)
```

Every credential must have the given agent as its subject. The presentation is signed with the Attestix server key (Ed25519 over Attestix's RFC 8785-style canonical JSON), so verify it with the Attestix verifiers (`verify_presentation`), not a generic W3C verifier.
